## Level 1 — Plain English

Employer selection is judgment. Adam and AI research the evidence; Adam approves
the companies for the current application/search cycle. Scout's deterministic
code then executes that decision. It does not invent an employer score or choose
substitutes. Application results can inform the next human decision without
automatically rotating the cohort.

Human + AI research/judgment → Product Owner approves employer cohort →
employers.json configuration → deterministic Job Scout monitoring → relevant job
population → Adam + ChatGPT application judgment → application state feeds future
cohort decisions.

Seven is valid because Adam explicitly approved seven: Muck Rack, LaunchDarkly,
BaubleBar, Airtable, Figma, Reddit and Rocket Lab. Earlier plans mentioned ten;
that target is superseded. ACTIVE means approved for this cycle, not a quota.
BENCH and PAUSED are explicit non-active pool values, not deletion commands.

Rocket Lab, Figma and Reddit keep the canonical identities created during the
pilot. SpaceX keeps its identity and source mapping but becomes PAUSED. Historical
jobs, applications, decisions and source observations remain. A synthetic test
proves that changing its pool leaves those facts intact. No private database was
opened or migrated to demonstrate this.

CPA analogy: changing this month's review population does not erase last month's
workpapers or transaction history. Configuration says what to search now; persisted
history says what was observed or explicitly recorded before.

Source health answers a separate question: can Scout retrieve compatible records
from each approved source? All seven checks succeeded. Airtable returned three
postings and zero recognized accounting/finance roles. That is an observed zero,
not a failed request or proof of exhaustive coverage. The full check returned 915
postings and 20 recognized roles before location and application restrictions.
It does not establish that Scout is more useful than separate ChatGPT/manual search.

## Level 3 — Code Literacy

Actual configuration fields, excerpted from the new Muck Rack entry:

```json
{
  "employer_id": "emp-muck-rack",
  "display_name": "Muck Rack",
  "greenhouse_boards": ["muckrack"],
  "approval_status": "APPROVED",
  "pool": "ACTIVE"
}
```

JSON stores named values. A canonical ID is a stable identity key, independent of
the display name. The board token names an explicitly verified Greenhouse source;
it is not guessed from the employer name. Unknown optional values remain null.

The existing source-selection comprehension includes:

```python
board for board, employer in mappings.items() if employer["pool"] == "ACTIVE"
```

This loop visits configured mappings and keeps ACTIVE entries. It does not score
employers or fill a required number of slots. Validation rejects duplicate IDs,
ambiguous source mappings and invalid fields before the search begins.

Actual configuration acceptance assertions include:

```python
self.assertEqual(run["active_employer_count"], 7)
self.assertEqual(len(run["jobs"]), 14)
```

The synthetic integration fixture supplies two jobs per employer. Fourteen output
jobs prove the configured seven feeds are used without reinstating Top-5 truncation.
Another assertion checks that SpaceX is PAUSED and cannot be selected via --boards.
