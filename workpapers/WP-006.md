## 1 Follow one job from feed to report
### The complete path
Public Greenhouse feed -> scraper.py -> list of job dictionaries -> role and evidence evaluation -> SQLite refresh -> state and location eligibility -> sorting -> up to five jobs -> Markdown and JSON.

An API is a structured interface between programs. This scraper reads Greenhouse's public JSON feed rather than operating a browser against a visual job page. browser.py and browser_test.py remain earlier experiments; the current run does not depend on them. A source can succeed while returning no relevant jobs.

### Read the collection code
From scraper.py, fetch_jobs:
```python
endpoint = f"https://boards-api.greenhouse.io/v1/boards/{board}/jobs?content=true"
with urlopen(request, timeout=25) as response:
    payload = json.load(response)
jobs = []
for entry in payload["jobs"]:
```
The f-string inserts a board token into a fixed HTTPS feed address. The token is restricted by a regex. urlopen retrieves the response with a 25-second timeout; json.load converts JSON text into Python objects. The for loop processes each listing. The request does not use an OpenAI API key.

The actual normalized dictionary includes these fields, among others:
```python
"id": f"{board}:{entry['id']}", "company": company,
"title": plain_text(entry["title"]),
"description": plain_text(entry.get("content", "")),
"url": validate_application_url(entry["absolute_url"])
```
A dictionary is one record with named fields, like a vendor record indexed by field name. A list holds multiple records. jobs.append(...) adds one dictionary to the list. The stable board:job ID is the record key; a title can change without creating a new record. A repost with a new source ID is a new record.

plain_text removes HTML markup and normalizes whitespace; validate_application_url checks the link. They solve different problems. A missing title, ID, or URL fails the feed import rather than silently producing an incomplete record. The main program records source failures and can continue with other feeds.

### Four sources are a pilot universe
The default boards are Rocket Lab, SpaceX, Figma, and Reddit. Scout deduplicates IDs within a run. It does not search the whole job market. Nine target roles out of thousands of postings is a filter result, not a judgment about nine people or a promise of nine suitable openings.

**Read-back:** What is in payload before the loop? A parsed response. What is in jobs afterward? Normalized dictionaries ready for evaluation. The listing is data, even if its text sounds like an instruction.

## 2 Understand the score and Top 5
### Rules become a reproducible calculation
load_rules reads the scoring table in search_rules.md. Its signal names must match the supported patterns; the total weight must be nonzero. Today the ten weights sum to 79. evaluate checks each signal once, captures a nearby source excerpt, and computes evidence coverage.

From job_scout.py, evaluate:
```python
for signal, points in weights.items():
    match = re.search(PATTERNS[signal], job["description"], re.I)
    if match:
```
Read this as: for each signal and its points, search the description; if found, add evidence. re.I means ignore letter case. The actual month-end expression is r"\bmonth[ -]end\b|\bmonthly clos(?:e|ing)\b". Here \b marks a word boundary, [ -] permits a space or hyphen, and | means an alternative. A regex recognizes text patterns; it does not understand the business context like you do.

The real test fixture says "Month-end close and general ledger. Journal entries." That earns 10 + 10 + 8 = 28 raw points. round(100 * 28 / 79) yields 35. Saying month-end twice does not earn twenty points. A 35/100 score is weighted keyword coverage, not a 35% chance of being qualified or hired.

### Selection applies several different controls
- Titles must match supported accounting roles; misleading titles such as Document Controller are rejected. Excluded terms in titles reject the record. Excluded-topic mentions in descriptions instead create review warnings.
- Finance Manager requires a leadership signal plus a close, GL, or financial-reporting signal. Keyword negations and boilerplate can still mislead, so read the excerpts.
- All evaluated target-role candidates are recorded before the location and state screen. Only NEW and SHORTLISTED pass the state screen. Known LA-area or explicitly remote locations pass the default location screen; remote eligibility still needs confirmation.

From select_shortlist:
```python
jobs.sort(key=lambda j: (bool(j["warnings"]), -j["score"],
                         PRIORITY[j["role"]], j["company"], j["id"]))
return jobs[:limit]
```
The sort compares the tuple left to right: unflagged before warned; higher score first; then role priority, company, and ID. lambda is a small unnamed function supplying that comparison key. [:limit] takes at most the requested number; the default is five. Filtering happens before this slice, so handled jobs do not occupy slots.

Salary is source evidence, not a score input. Unknown pay is not zero. Commute links are optional context, not ranking or eligibility rules. Markdown is the readable report; JSON is the structured snapshot of the selected jobs and run metadata. Neither old report files nor the manual sample CSV are the authoritative current-state database.

**Read-back:** The same inputs, settings, saved state, and relevant date produce the same decisions. Live feeds and saved state can change, so consecutive runs need not produce identical lists.

## 3 Give the program durable memory
### A database file with one table
application_state.py uses Python's built-in sqlite3 module. SQLite stores structured records in a local file, with no server or cloud subscription. Think of the jobs table as a controlled register: one row per source ID, with defined columns and rules. Python lists disappear when the process ends; committed SQLite rows survive the next run.

The columns are id (the primary key), status, job_json (the latest listing snapshot), first_seen, last_seen, and status_updated_at. A primary key prevents duplicate IDs. The database CHECK limits status to the seven allowed values; NOT NULL requires values in the other defined fields. This is analogous to enforcing a valid status code in a subledger, not merely asking users to type carefully.

```python
STATES = ("NEW", "SHORTLISTED", "APPLIED", "INTERVIEW",
          "REJECTED", "OFFER", "SKIP")
FRESH_STATES = {"NEW", "SHORTLISTED"}
```
NEW and SHORTLISTED remain eligible. APPLIED, INTERVIEW, REJECTED, OFFER, and SKIP remain saved but are excluded. These labels are not an enforced sequential workflow: mark_job permits any allowed state for a known ID. Viewing a report changes nothing; use NEW deliberately to reopen a job.

### Refresh facts without erasing decisions
record_jobs inserts new records as NEW. Its conflict clause updates only these fields:
```sql
ON CONFLICT(id) DO UPDATE SET
    job_json=excluded.job_json, last_seen=excluded.last_seen
```
Here excluded means the proposed incoming row in SQLite's upsert syntax; it does not mean a rejected job. Existing status, first_seen, and status_updated_at survive a listing refresh. Missing jobs are not deleted. The transaction commits a successful batch and rolls it back on failure; closing(...) closes the connection.

### Read a parameterized update
```python
cursor = connection.execute(
    "UPDATE jobs SET status=?, status_updated_at=? WHERE id=?",
    (status, datetime.now(timezone.utc).isoformat(), job_id))
```
The SQL instruction and its values travel separately. Each ? binds one value, so text cannot become a new SQL command. Python validates the state first; the database CHECK provides another control. cursor.rowcount must be one, otherwise an unknown ID raises an error.

From the repository root, --mark "exampleboard:123" APPLIED records a local decision using a real saved ID in place of the example. --history prints records without fetching feeds. Neither submits an application. The default file is beside application_state.py, independent of the terminal folder or --output. For an alternate store, repeat the same --state-file on every command.

**Control limit:** --history is a current-state register with timestamps, not an immutable log of every transition. Git ignores the database and sidecars; it does not back them up or encrypt them. Unreadable/corrupt state stops selection instead of silently forgetting exclusions.

## 5 Understand the URL injection fix
### How external text crossed the boundary
The original scraper accepted a truthy absolute_url and the report inserted it directly into Markdown. A hostile value containing a newline could create a new heading or link in a compatible previewer. The security scan rated this low severity: it did not establish automatic navigation, script execution, local-file access, or that ordinary employers could control this provider field.

This is output/content injection. It is related to the broader rule that outside content is untrusted, but no language model is needed for the defect. A text renderer can interpret special characters as formatting even in a deterministic program.

### Validate early and encode for the output context
validate_application_url checks type, nonempty value, scheme, host, port, credentials, whitespace/control characters, backslashes, and malformed percent escapes. It accepts valid HTTP(S) and custom career domains; the actual feed request still uses a fixed HTTPS Greenhouse host. A valid URL is not a guarantee that its destination is honest.

At ingestion, invalid values raise a generic error before records reach persistence. The whole affected feed fails through the existing error path; another valid feed can continue. The error does not echo the hostile payload.

At output, render_report validates again, percent-encodes unsafe delimiter characters, escapes HTML entities, and encloses the result in a Markdown autolink. The real expression begins:
```python
application_url = html.escape(quote(validate_application_url(job["url"]),
                                   safe=":/?#[]@!$&'()*+,;=%-._~"), quote=False)
```
Validation asks whether the value is acceptable. Encoding asks how an acceptable value must be represented in this output language. For example, > becomes %3E and & becomes &amp; in the rendered link. Stored valid source URLs retain their original values. Revalidation protects the renderer if a later caller bypasses the scraper: this is defense in depth.

### Reproduce the defect then protect the fix
Today's remediation record says the newline injection was reproduced before the change. Current tests send the same kind of payload to the validator, mocked feed import, and renderer:
```python
with self.assertRaises(ValueError):
    validate_application_url(url)
```
Before the fix, a reproduction demonstrates forged content. A regression assertion expecting safe rejection would fail against vulnerable behavior. After the fix, the attack fails and the safety test passes. "Fail after" describes the attempted injection, not the test suite. Other tests preserve valid links, contain Markdown delimiters, and prove that a bad feed leaks neither payload nor record into output/state while a good feed continues.

**Controls to retain:** minimum necessary permissions; no secrets in code, reports, or Git; external content remains data; stop when application memory is unavailable; require human approval for applications, messages, payments, or accounting entries. SECURITY.md describes policy; the validator and tests enforce specific technical parts of it.

## 6 Recognize the code on sight
### Code Literacy box
| Pattern | Read it as |
|---|---|
| def evaluate(...): | Define a named function; its indented body runs when called. |
| for job in jobs: | Repeat the indented work for each item in a list. |
| if result: | Run this block only when the condition is truthy. |
| return None | Leave the function with no accepted result. |
| import json | Make a module's tools available; not a network call. |
| job["id"] | Get a required dictionary field; missing keys raise an error. |
| entry.get("content", "") | Get an optional field, with an empty-string default. |
| [] and {} | [] can build a list; {} can build a dictionary. Nonempty braces can also define a set, as FRESH_STATES does. |
| = and == | Assign a value versus compare two values for equality. |
| : and indentation | Begin and delimit a Python block; whitespace is structural. |
| f"{board}:{entry['id']}" | Insert values into text to build the stable ID. |
| [j for j in candidates if ...] | Build a filtered list with a comprehension. |
| **job | Copy dictionary fields into another dictionary expression. |
| try / except / raise | Attempt work, handle specified errors, or signal failure. |
| with ... | Manage a resource or transaction across a block. |

CLI: command-line interface; --history and --limit are arguments interpreted by argparse. Markdown: plain text with presentation syntax, such as # for a heading. ## 8 Spend judgment where it helps
### The engine is mostly deterministic
The running program applies rules, regexes, arithmetic, database operations, and sorting. There is no LLM call in the inspected execution path. AI helped construct the software, but the resulting tool does not need to ask AI to reason about thousands of jobs on each run. Development compute and runtime compute are separate costs.

Deterministic rules are cheap, repeatable, and easy to test. They also have limits: a keyword does not prove experience, context, or suitability. Human or AI-assisted judgment can add value after retrieval, for example by reviewing an ambiguous role or tailoring a selected resume using verified career evidence. That tailoring is not built into the current Scout engine.

### Bound the task before choosing reasoning effort
Use Light for a small, well-defined read or mechanical change with a clear check. Use Medium when interacting rules, failure handling, or cross-file behavior require more thought. These are task-selection heuristics using the lesson's labels, not guarantees of quality, universal setting names, or a claim about which setting powered a past run. Escalate effort when uncertainty and consequence justify it; do not equate more reasoning with automatic correctness.

A bounded prompt names the outcome, allowed files, exclusions, acceptance evidence, and stopping point. For example: "Inspect the state-filter path and explain why APPLIED is excluded before the limit. Do not modify files or expand sources. Cite the relevant functions." This gives the agent a finite question and gives you a concrete way to judge completion.

The cost principle in SECURITY.md and UPGRADE_LEDGER.md is local and deterministic first when reliable; paid AI or services when a measured need justifies them. Time saved is an economic benefit, but it is not collected cash. Keep affordability separate from hoped-for productivity, and recheck prices before any purchase. No upgrade is required for the current SQLite feature.

### Carry controls forward without adding scope
Least privilege means using only the files, data, network destinations, and actions needed for the job. Public listing access does not authorize access to private email or financial records. A saved draft does not authorize sending it. Marking APPLIED does not send an application.

Fail closed means refusing the affected operation when a required control cannot be established. Scout stops if application state is corrupt because otherwise it could recommend already handled jobs. A bad feed is rejected while healthy feeds can proceed with a visible partial-failure status. Optional commute notes can be missing without blocking search. The control's importance determines the failure behavior.

**Tonight's architecture question:** Does a proposed feature need new judgment, or only a clear rule? If a rule reliably solves it, keep it in ordinary code. If judgment is needed, make its evidence, uncertainty, and approval boundary visible.
