## Level 1 — Plain English Machine

Adam initially understood “AI agent” as something closer to ChatGPT/Atlas: a
reasoning system that interprets context and adapts to a question. What the project
primarily built was a different machine:

**Atlas reasons about the project → Codex builds and tests it → Python/SQLite
executes defined rules and remembers facts.**

Codex can intelligently build deterministic software without giving that software
Codex's reasoning abilities. The distinction was insufficiently explicit at the
start. Job Scout became the real-world experiment that made it visible; this was
not a tutorial intentionally designed that way from the beginning.

### The concrete example

After Task 5 was committed, Adam reports a manual run using the verified Python
runtime: **915 postings → 20 recognized accounting/finance roles → 18 displayed
under normal location policy; all 18 were unhandled by job state**. The earlier
Task 5 source check had reached all seven approved feeds successfully. The private
runtime report remains ignored; this workpaper does not reproduce private history.

Scout did not consider the whole labor market and reason its way to those 18 roles.
It fetched configured feeds, applied encoded title/location rules and displayed
the resulting population with saved state. Eighteen unhandled roles is not a claim
that all 18 pass employer-selection controls or are confirmed geographically suitable.

Adam's independent ChatGPT/Atlas public-web comparison found substantially the
same useful population across these seven employers. The possible extra Figma
Senior Technical Revenue Analyst role was reviewed and not of application interest.
That difference did not justify expanding the classifier. A difference in retrieval
is evidence to judge, not automatically a defect to fix.

Scout demonstrated strong reduction/repeatability within its configured sources.
It did not demonstrate broader-market completeness, measured savings or commercial
validation. A clean Greenhouse API is convenient technically; the business consequence
is that employers on other career systems are outside the search. That consequence
needed earlier challenge and explanation. It is a product boundary, not a security
defect or an implementation failure.

### Why both reasoning and traditional software matter

Reasoning AI can interpret ambiguity, compare unfamiliar evidence, synthesize and
research across broader sources when appropriate tools/access exist. Its output may
vary, its coverage still needs checking, and repeated reasoning can cost more.
Deterministic software repeatedly executes defined rules quickly, stores history
and makes controls reproducible and testable. Neither resource is universally better.

CPA analogy: a repeatable reconciliation routine can consistently flag differences;
professional judgment determines whether the population is complete, an exception
matters, and the control serves the objective. Passing the routine's tests does not
prove that the chosen population or business premise was right.

The remaining Job Scout question is whether repeatability, state, scale and controls
add enough value over AI-assisted discovery to justify maintenance. Future projects
start by asking what already achieves the outcome and what gap custom software would
close. Working code alone is not proof that more code should be built. Available
subscription capacity is not a reason to invent development work.

## Level 2 — Component Map

```text
Adam / Product Owner and domain judgment
                    ↕
Atlas / reasoning, interpretation and premise challenge
                    ↕
Codex / repository implementation and verification
                    ↕
Deterministic software + local database
                    ↕
External structured sources / configured Greenhouse feeds
```

This is a responsibility map, not a claim that Atlas or Codex is called during a
normal Scout run. The current runtime uses Python rules and SQLite; it does not
make a reasoning-AI call to classify each job.

| Layer | What happens here | Boundary to recognize |
| --- | --- | --- |
| Adam | Defines useful outcomes, supplies context, approves assumptions and consequential decisions | Evidence supports contextual judgment |
| Atlas | Interprets, researches, synthesizes and challenges the premise | Reasoning claims and source coverage still require verification |
| Codex | Reads the repository, implements bounded changes and checks behavior | The implementation agent is distinct from the runtime it creates |
| Python / SQLite | Fetches configured feeds, applies rules, reports jobs, preserves explicit state/history | Defined logic cannot discover an unconfigured source by itself |
| Greenhouse sources | Supply external job records | Availability is not completeness; external content remains untrusted data |

The useful division of work is provisional. An accounting workflow might eventually
use deterministic preprocessing, reasoning for ambiguous exceptions and human
approval. A benchmark must establish the gap before selecting that architecture.

## Level 3 — Code / System Literacy

Read these as landmarks in the real repository, not a syntax memorization exercise.

| Concept | Where to recognize it | What it means |
| --- | --- | --- |
| API / source boundary | `scraper.py`, `fetch_jobs` | Structured external input enters here; this boundary limits what Scout can see |
| Configuration | `employers.json`, `employer_registry.py` | Explicit approved identities, board mappings and ACTIVE placement select the population |
| Deterministic filter | `job_scout.py`, `evaluate`; `search_rules.md` | Encoded rules decide recognition/coverage; this is not free-form AI judgment |
| Database / state | `application_state.py`, `application_lifecycle.py`, SQLite | Local persistence records observations, explicit application facts and history across runs |
| Tests | `test_*.py` | Synthetic examples check specified behavior; they do not prove market completeness or product value |
| Reasoning layer | Adam's separate Atlas/ChatGPT research and analysis | Interprets context and differences outside the deterministic runtime |
| Source limitation | Configured Greenhouse boards | A valid result can still omit the wider market because its input universe is bounded |
| Acceptance benchmark | Same seven employers compared by Adam | Checks practical useful output; distinguish this from test passing and source reachability |

Compact recognition box: **Python** executes instructions; a **CLI** command starts
an operation; **JSON** carries structured named values; **SQLite** persists local
records; **tests** check examples; **Git** versions intended code/docs, not ignored
private data; **security controls** bound access and treat retrieved content as data.
